## 1. Decided now

### Stack
| Area | Choice |
| --- | --- |
| Repo | pnpm monorepo: `client/`, `server/`, Node 24, TypeScript |
| Frontend | React 19, Vite, Tailwind 4, TanStack Query, React Router, Vitest + Testing Library |
| Backend | Node.js, Fastify 5, Zod (`fastify-type-provider-zod`) |
| DB | PostgreSQL + Prisma |
| Cloud | AWS |
| Lint / format | oxlint, Prettier, Husky, lint-staged |

### Storage (S3)
- One package: `@aws-sdk/client-s3` (+ `@aws-sdk/s3-request-presigner`).
- No keys in code. Default credential chain: IAM role on AWS, `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` in env for local only.
- Used for: slide files, draft/temp files, exports. Videos live in Cadmore.

### Video (Cadmore)
- Code against a `VideoProvider` interface (upload, anonymize, stream URL, captions, transcript, delete).
- Ship a `MockVideoProvider` now; real `CadmoreVideoProvider` once API key and docs arrive.
- Config via env for now: `CADMORE_API_URL`, `CADMORE_API_KEY` (placeholders).
- PRD fallback (Kriyadocs processing service) can be a second implementation of the same interface.

### Auth and links
- Reviewer access: signed secure links, one reviewer + one manuscript, 14-day expiry (NFR-7).
- ORCID: later.

### Jobs / queue
- `pg-boss` on PostgreSQL: no extra infra (accessibility-pdf needs Redis; we don't).
- Jobs: video-processing callbacks and polling, reminders, link expiry, 90-day retention delete (NFR-4), slide conversion and scan.

### Slides
- PDF/PPTX to page images, 5–8 slides; double-blind scan for names, emails, logos (FR-2.7, FR-2.12).

### Observability and CI
- Structured logs (pino via Fastify), `/api/health`, OpenTelemetry later.
- GitHub Actions: lint, test, build, Docker image.

### Platform integration
- Kriyadocs portal only for R1. Adapter layer so Editorial Manager / ScholarOne can follow in R1.x.

### Compute and processing model
Reference (accessibility-pdf): one Docker image serves API + web on one port, run with Docker Compose on a VM, IAM role for AWS, TLS at the load balancer, SIGTERM-aware shutdown.

Which Node mechanism for which work:
| Work | Mechanism | Why |
| --- | --- | --- |
| HTTP, S3, DB, Cadmore calls | Default event loop (libuv) | I/O bound; libuv thread pool is automatic |
| Video anonymize / transcode / captions | Cadmore (mock now) | Not our CPU |
| Parsing untrusted files (PDF/PPTX scan) | `child_process` fork | Crashed or memory-hungry file kills only that process; same pattern as accessibility-pdf `pacReader` |
| Light CPU (hashing, text checks) | `worker_threads` | Shared process, no event-loop block |
| Scaling | More containers/tasks | App is stateless; `cluster` not needed |
| Job runner | Same image, second process (`worker` command) running pg-boss | API and jobs scale separately |

If we ever process video ourselves (fallback): `spawn` ffmpeg in a worker process, never inside the API.
